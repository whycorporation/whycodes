# test(cli): bring whycodes-cli to 100% (1/17 -> 17/17)

Parent: #57. Blocks Phase 4 workspace 100% gate.

## Problem
`whycodes-cli` is ~69.6% line coverage and the lowest file-test ratio (`cfg(test)` in 1 of 17 production files). It is the composition root (`main.rs`, `args.rs`, `cmd/*`, `upgrade.rs`). CI currently has **no** per-crate floor for it.

## Surfaces
- `crates/cli/src/main.rs` — version short-circuit, runtime selection, dispatch
- `crates/cli/src/args.rs` — clap tree
- `crates/cli/src/cmd/{auth,config,debug,github,helpers,mcp,memory,mod,provider,run,serve,session,upgrade}.rs`
- `crates/cli/src/upgrade.rs` — self-update
- Existing: `crates/cli/src/tests.rs` (sibling, llvm-cov ignored), `crates/cli/tests/cli_args.rs`, `crates/cli/tests/sdk_v1.rs`

## Proposal
Add `#[cfg(test)]` coverage so every production line is hit (or is an unreachable `#[cfg]` / `unreachable!` documented in the PR). Prefer tests in `tests.rs` so `check_coverage_floors.py` still skips them. At least one integration/golden path (`cli_args` or new `tests/`).

Focus: arg parsing, completions, doctor/debug, session list, config show, mcp wiring, runtime_for / command_needs_multi_thread, upgrade dry paths. Mock network; do not start a real TUI.

## Acceptance
- [ ] `FLOORS` includes `("whycodes-cli", 100.0)`.
- [ ] File-test ratio >= 80% (tests.rs sibling counts; or `mod tests` in the remaining files).
- [ ] `cargo test -p whycodes-cli` green; no new flakes.
- [ ] `scripts/coverage.sh` prints `OK whycodes-cli: … 100.0% floor 100%`.

## Validation
```bash
cargo test -p whycodes-cli
cargo build -p whycodes-cli
scripts/coverage.sh
```
